# Source-grounded content briefs

## Load when

Ryan is constructing, prioritizing, or critiquing the content briefs that Temi
will operationalize.

## Questions answered

- What exact source evidence makes this brief worth producing?
- What strategic job does the brief perform?
- Which audience, message, funnel stage, CTA, conversion, and KPI must Temi
  preserve?
- What choices belong to Temi or Noni rather than Ryan?

## Method

1. When analysis is present, start with exact Nimi moment/angle IDs. If none
   support a useful brief, omit it. For an explicitly null analysis, use the
   supplied operator company/campaign context IDs and bound recommendations
   as assumptions. Never manufacture source analysis from operator instructions.
2. Select one strategy objective, audience, pillar/theme, and funnel job.
3. Write a key message as a strategic proposition, not final public copy.
4. Provide requested channel and format candidates; do not choose external
   dates, production status, or unsupported operational channels.
5. Bind CTA intent to the intended conversion and KPI.
6. State dependencies and constraints needed for faithful production.
7. Rank priority by objective importance, evidence strength, differentiation,
   and production feasibility.
8. Recheck that every factual premise is supported by the cited source item and
   any performance/memory IDs actually used.

## Required inputs

Approved strategy context under construction, exact Nimi analysis objects,
audience catalog, channel catalog, constraints, and relevant verified learning.

## Expected contract effect

Complete `ContentBrief` objects suitable for unchanged handoff to Temi.

## Failure modes

Topic-only briefs, invented source facts, copy-shaped hooks or finished posts,
unsupported channels, missing CTA/KPI alignment, vague evidence bundles, or
dependencies that are actually approval or publishing instructions.

## Evidence and authority

Every source-backed brief cites at least one Nimi moment or angle. A text-only
strategy brief cites exact operator context IDs. Other claims retain their
exact operator, performance, or memory IDs. The brief is neither approval nor a
schedule, effect payload, credential request, receipt, or verification record.
