---
title: "The Pipeline"
description: "Stage by stage: ingest, transcribe, understand, strategize, approve strategy, plan, draft, approve effects, publish, verify, learn."
---

Harmonia's pipeline is a linear stage machine. Each completed stage persists its payload and atomically records the next trigger in a Firestore outbox. Pub/Sub publication is claimed and finalized from that outbox; the durable tick recovers pending delivery after a crash.

```mermaid
flowchart LR
    Q[queued] > I[ingest] > T[transcribe] > U[understand] > S[strategize] > SA[awaiting_strategy_approval] > P0[plan] > D[draft] > A[awaiting_approval]
    A -- approved --> P[publish] > V[verify] > L[learn] > C[complete]
    A -- rejected/skipped --> C2[complete]
```

## ingest

Resolves the video id, fetches official metadata (YouTube oEmbed; Data API adds duration when `YOUTUBE_API_KEY` is set), downloads bestaudio via yt-dlp, and — when the Data API is unavailable — measures the real duration locally with ffprobe so downstream stages never see a zero-length timeline.

## transcribe

Gemini 3.5 Flash returns `{language, segments:[{id,startSec,endSec,text}]}` from the audio inline payload.

## understand

For video jobs, Harmonia gives Nimi (`nimi_analyst`) a typed source ID/digest, individually identified transcript segments, bounded media/frame evidence, verified performance observations, and eligible Memory Bank facts with Firestore provenance. Nimi returns exact-quote moments and qualified source, trend, meme, performance, or memory angles. Each item declares evidence references, assumptions, and confidence. Deterministic validation enforces digest identity, quote and time bounds, frame provenance, evidence-kind separation, and Nimi's analysis-only authority before persisting the complete `SourceAnalysis` plus canonical SHA-256 digest. Ryan receives that exact persisted object. Brief-only concepts still pass through Nimi as an identified zero-time source segment.

The durable stage order is `understand → strategize → awaiting_strategy_approval → plan → draft`. Before Ryan runs, the exact typed evidence catalog—including eligible Memory Bank IDs and Firestore provenance—is persisted and later revalidated in the same transaction that accepts the proposal. Strategy approval is bound to the canonical SHA-256 digest. One rejection with operator feedback permits strategy version 2; a second rejection ends the job. Temi cannot run without an approval record matching the current digest.

## plan

Temi (`temi_editorial_planner`) receives the exact approved Ryan strategy, typed Nimi analysis, supported channel/format capabilities, existing commitments, production capacity, cadence constraints, and evidence-backed posting-window observations. Temi agentically proposes the complete four-week editorial operationalization: sequencing, cadence, channels, formats, publication windows, production deadlines, dependencies, priorities, required assets, assumptions, and confidence. Temi has no tools and cannot write final copy, approve anything, mutate an external calendar, schedule in an external system, or execute an effect.

Deterministic code validates the plan against the approved strategy digest and closed-world evidence, rejects unsupported channels/formats and authority claims, computes the canonical SHA-256 digest, and persists the complete plan plus evidence lineage in Firestore. It then selects exactly one highest-scoring eligible item and records its lifecycle. Memory and approved strategy context inform planning but never authorize selection, scheduling, approval, or effects.

Dashboard and chat confirmations call the same tenant-scoped decision transaction. Telegram receives expiring digest-bound nonces via the official Bot API; a rejection callback must be completed with an authenticated reply containing operator notes before it can request Ryan's single revision.

## draft

The production workflow passes only the selected editorial item, its exact Ryan brief, and the referenced Nimi moments/angles to Noni (`noni_copywriter`). Dara (`dara_editor`) then receives the exact immutable input and draft and returns a seven-dimension `EditorialAssessment`, not workflow metadata or replacement copy. Deterministic code validates every check and issue, assigns review identity/lineage/time, runs one original plus at most one issue-bound revision, requires the second assessment to resolve every prior issue and accept, and persists the canonical-digested production trace. The rest of the plan is not exposed as drafting authority. Stage code derives `publish_x_post` proposals from the exact accepted text and adds the content pack, meme image generations, captioned vertical clips, and stitched highlight reel.

Every action lands with `requiresApproval`, risk level, and its own idempotency key material.

## awaiting_approval

Hard gate. Approvals arrive through the dashboard queue, chat ("approve job \<id\>"), or a Telegram inline-button callback — all through the same decision engine, which records who approved what and when.

## publish

Executes approved actions in order, checking receipts first for idempotency:

| Action | Effect |
|---|---|
| `publish_x_post` | POST to X API v2 `/2/tweets`; receipt carries post id + URL |
| `export_content_pack` | Markdown bundle of moments, angles, drafts stored with a digest |
| `generate_image` | Gemini image bytes into the asset store |
| `render_clip` / `render_reel` | Real ffmpeg cuts/captions/reframes into the asset store |

Failures are classified: permanent errors stop the job visibly, transient errors nack for redelivery.

## verify

Independent re-fetch of every executed action: tweets re-read from X by id, pack digests compared against Firestore, asset digests re-checked from the store. Results are immutable verification records — the receipt says what we *did*, verification says what is *true*.

## learn

Measures published posts via public metrics, derives evidence-linked takeaways, and stores eligible facts for future Nimi analysis and Ryan strategy inputs.
